# QUACK Governance

## Project Structure

QUACK is an open-source AI Operating System governed by a benevolent dictator model with a clear contribution framework.

## Roles

### Maintainer
- Owns the project vision and roadmap
- Makes final decisions on architecture, design, and scope
- Manages releases and versioning
- Reviews and merges significant contributions
- Appoints additional maintainers

### Committer
- Regular contributor with proven track record
- Can review and approve routine changes
- Participates in architecture discussions
- Mentors new contributors

### Contributor
- Submits pull requests, issues, and documentation
- Participates in community discussions
- Follows the project's code of conduct and contribution guidelines

## Decision Making

- **Architecture decisions:** Documented as ADRs (Architecture Decision Records) in `docs/adr/`
- **Feature decisions:** Discussed via GitHub issues with community input
- **Emergency decisions:** Maintainer may make urgent decisions for security or stability

## Release Process

See [RELEASE_PROCESS.md](./RELEASE_PROCESS.md) for detailed release workflow.

## Communication

- **GitHub Issues:** Bug reports, feature requests, questions
- **GitHub Discussions:** Community conversations, Q&A, proposals
- **Pull Requests:** All code changes, reviewed before merging
- **ADRs:** All significant architecture decisions documented

## Code of Conduct

All participants must follow our [Code of Conduct](./CODE_OF_CONDUCT.md).
